# 시장 추세 1일 지연 문제 분석 및 장중 데이터 활용 방안

## 1. 문제 정의

현재 theme-analysis 프로그램은 시장 상황과 추세를 **약 1일 늦게** 따라가고 있다.
사용자에게 가장 유용한 정보(어떤 테마가 부상하고 있는가, 어떤 종목에 자금이 몰리고 있는가)가
**이미 지난 흐름**을 보여주는 수준에 그치고 있다.

## 2. 원인 분석

### 2.1 현재 데이터 파이프라인 타임라인 (KST)

```
07:30  Theme Forecast        — 전일 종가 기반 장전 AI 예측
09:05  Daily Theme Analysis  — 전일 종가 + 당일 시초 AI 테마 분석 (메인)
09:10  Macro Futures          — 선물/지수 수집
09:28  Daily Theme Analysis  — 2차 실행 (09:05와 동일 로직)

09:31  Investor Data #1      — 수급 수집 시작
10:00  Forecast Intraday #1  — 장중 AI 재예측 ★
10:01  Investor Data #2
11:00  Intraday History
11:30  Refresh Stock Data    — 전체 갱신 (AI 분석 제외)
11:31  Investor Data #3
12:00  Intraday History
13:00  Forecast Intraday #2  — 장중 AI 재예측 ★
13:21  Investor Data #4
```

### 2.2 핵심 지연 원인

| 원인 | 설명 |
|------|------|
| **AI 테마 분석이 장 시작 직후 1회 실행** | `daily-theme-analysis.yml`이 09:05/09:28에만 실행. 입력 데이터가 전일 종가 + 장 시작 직후 시세 → 당일 오전에 발생하는 급변 반영 불가 |
| **장중 재예측(10:00, 13:00)이 제한적** | `theme-forecast-intraday.yml`이 2회 실행되지만, `latest.json`의 `theme_analysis` 필드를 직접 갱신하지 않고 별도 `theme-forecast.json`에 저장 |
| **장중 수집 데이터가 분석에 미활용** | 수급(7회), 분봉(7회), 매물대(2회) 등 풍부한 장중 데이터가 수집되지만 **차트 표시용**으로만 사용. AI 분석이나 종목 순위 재계산에 투입되지 않음 |
| **등락률/거래량 순위가 장중 갱신 부족** | `collect-investor-data.yml`이 거래량/거래대금/등락률 TOP30을 갱신하지만, 이 갱신된 순위가 AI 분석에 피드백되지 않음 |
| **프론트엔드에 "지금 무엇이 움직이는가" 뷰 부재** | 장중 급등/급락, 수급 급변 종목을 실시간으로 하이라이트하는 UI가 없음 |

### 2.3 수집은 되지만 분석에 미활용되는 장중 데이터

| 데이터 | 수집 빈도 | 저장 위치 | 현재 활용 | 잠재 가치 |
|--------|----------|---------|---------|---------|
| 종목별 수급 변동 (외국인/기관) | 7회/일 | investor-intraday.json | 차트 표시만 | **수급 급변 감지** |
| 시간대별 등락률 (30분/1시간) | 7회/일 | intraday-history.json | 차트 표시만 | **모멘텀 전환 감지** |
| 거래량/거래대금 TOP30 | 7회/일 | latest.json | 목록 표시만 | **핫 종목 실시간 추적** |
| 프로그램 매매 동향 | 7회/일 | latest.json, investor-intraday.json | 일부 미표시 | **기관 방향성 판단** |
| 매물대 (상위 80종목) | 2회/일 | volume-profile.json | 팝업 표시만 | **지지/저항 돌파 감지** |

## 3. 개선 방안

### 방안 A: 장중 모멘텀 대시보드 (프론트엔드 개선, 신규 수집 불필요)

**핵심 아이디어**: 이미 수집 중인 장중 데이터를 가공하여 "지금 무엇이 움직이는가"를 보여주는 섹션 추가.

#### A-1. 장중 급등/급락 감지 (intraday-history.json 활용)

현재 `intraday-history.json`에는 모든 종목의 30분/1시간 단위 등락률이 기록되어 있다.
이를 활용하면:

- **최근 1~2시간 등락률 급변 종목** 추출 가능
  - 예: 30분 전 대비 등락률이 ±2% 이상 변동한 종목
  - 직전 구간 대비 거래량이 2배 이상 급증한 종목
- **시간대별 모멘텀 방향 변화** 추적 가능
  - 오전 하락 → 오후 상승 전환 종목 (바닥 반등 신호)
  - 연속 상승 구간 종목 (강한 매수세)

**구현 방식**: 프론트엔드에서 `intraday-history.json`의 최신 날짜 데이터를 분석하여 정렬/필터링.
별도 백엔드 수집 작업 불필요.

```
필요 작업:
- 프론트엔드: 장중 모멘텀 컴포넌트 신규 (IntradayMomentum.tsx)
- 백엔드 변경: 없음 (기존 데이터 활용)
```

#### A-2. 수급 급변 알림 (investor-intraday.json 활용)

`investor-intraday.json`의 스냅샷 간 차이를 계산하면:

- **외국인/기관 순매수 급변 종목** 감지 가능
  - 예: 직전 스냅샷 대비 외국인 순매수가 +5만주 이상 증가한 종목
  - 기관이 매도에서 매수로 전환한 종목
- **수급 추세와 가격 괴리** 감지
  - 가격 하락 중이나 외국인/기관 순매수 증가 → 저가 매집 신호
  - 가격 상승 중이나 외국인/기관 순매도 → 차익 실현 경고

**구현 방식**: 프론트엔드에서 snapshots 배열의 연속된 항목 간 delta 계산.

```
필요 작업:
- 프론트엔드: 수급 급변 섹션 (StockList 상단 또는 별도 탭)
- 백엔드 변경: 없음
```

#### A-3. 거래대금 순위 변동 추적 (latest.json 활용)

`collect-investor-data.yml`이 7회/일 거래대금 TOP30을 갱신한다.
이를 **이전 스냅샷과 비교**하면:

- **새로 TOP30에 진입한 종목** = 시장 관심 급증
- **순위가 크게 상승한 종목** = 자금 유입 가속
- **TOP30에서 이탈한 종목** = 관심 감소

**제한**: 현재는 스냅샷 간 비교 데이터가 저장되지 않음. 구현하려면 이전 순위를 캐싱하거나 별도 저장 필요.

```
필요 작업:
- 백엔드: collect_investor_data.py에서 이전 순위 비교 후 변동 정보 저장
- 프론트엔드: 순위 변동 표시 (↑N, NEW 등)
```

### 방안 B: 장중 AI 재분석 강화 (기존 워크플로우 개선)

**핵심 아이디어**: 이미 존재하는 `theme-forecast-intraday.yml` (10:00, 13:00)의 결과를 메인 대시보드에 직접 반영.

#### B-1. theme-forecast.json → 프론트엔드 직접 통합

현재 상태:
- `daily-theme-analysis.yml` → `latest.json.theme_analysis` (09:05, 09:28)
- `theme-forecast-intraday.yml` → `theme-forecast.json` (10:00, 13:00)
- 프론트엔드의 `AIThemeAnalysis.tsx`는 `latest.json.theme_analysis`만 표시

개선:
- `AIThemeAnalysis.tsx`가 `theme-forecast.json`도 로드하여, 더 최신인 쪽을 표시
- 또는 장중 재예측 결과를 `latest.json.theme_analysis`에 병합

```
필요 작업:
- 프론트엔드: useThemeForecast 훅 추가, AIThemeAnalysis에서 최신 데이터 선택 로직
- 또는 백엔드: theme-forecast-intraday.yml에서 latest.json 직접 갱신
```

#### B-2. 장중 재예측에 수급 데이터 추가 투입

현재 `forecast_main.py --intraday`는 거래대금/등락률/거래량 TOP 종목을 Gemini에 전달.
여기에 **장중 수급 변동 데이터**를 추가하면 더 정확한 예측 가능:

- 외국인/기관 순매수 상위 종목 목록
- 프로그램 매매 방향 (시장 전체)
- 장중 등락률 변동 (모멘텀 데이터)

```
필요 작업:
- forecast_main.py 수정: investor-intraday.json, intraday-history.json 로드 → 프롬프트에 추가
- Gemini 프롬프트 개선: 수급 흐름 + 모멘텀 데이터 포함
```

#### B-3. 장중 재분석 빈도 증가

현재 2회(10:00, 13:00) → **3~4회**로 확대:
- 10:00, 11:30, 13:00, 14:30
- Gemini API 비용: 2.5-flash 모델 사용 중이므로 추가 비용 미미

```
필요 작업:
- 외부 cron-job 추가 (11:30, 14:30)
- 또는 theme-forecast-intraday.yml 스케줄 확장
```

### 방안 C: 장중 실시간 스코어링 (신규 기능)

**핵심 아이디어**: AI 분석 없이도, 장중 수집 데이터를 규칙 기반으로 스코어링하여 종목 우선순위를 실시간 재계산.

#### C-1. 실시간 종합 점수 (Realtime Score)

각 종목에 다음 요소를 가중 합산한 점수를 부여:

| 요소 | 가중치 | 데이터 소스 | 갱신 주기 |
|------|--------|-----------|---------|
| 등락률 | 20% | latest.json (변동률) | 7회/일 |
| 거래대금 순위 | 20% | latest.json (trading_value) | 7회/일 |
| 외국인 순매수 | 20% | investor-intraday.json | 7회/일 |
| 기관 순매수 | 15% | investor-intraday.json | 7회/일 |
| 모멘텀 (최근 2시간 변화) | 15% | intraday-history.json | 7회/일 |
| 매물대 돌파 여부 | 10% | volume-profile.json | 2회/일 |

**장점**: Gemini API 호출 없이 즉시 계산 가능. 프론트엔드에서 클라이언트 사이드 계산 가능.

```
필요 작업:
- 프론트엔드: 점수 계산 유틸 + 점수 기반 정렬 옵션
- 백엔드 변경: 없음 (기존 데이터 활용)
```

#### C-2. 수급-가격 괴리 경고

종목별로 **수급 방향과 가격 방향의 괴리**를 감지:

- 가격 ↓ + 외국인 ↑ + 기관 ↑ = "기관 저가매집" 신호 (긍정)
- 가격 ↑ + 외국인 ↓ + 기관 ↓ = "개인 주도 상승" 경고 (주의)
- 가격 ↑ + 거래량 급감 = "동력 약화" 경고

```
필요 작업:
- 프론트엔드: StockCard에 괴리 경고 뱃지 추가
- 백엔드 변경: 없음
```

### 방안 D: 장중 핫 테마 트래커 (신규 섹션)

**핵심 아이디어**: AI 테마 분석에 포함된 종목들의 장중 성과를 실시간 추적하여 "지금 어떤 테마가 살아있는가"를 표시.

#### D-1. 테마별 장중 성과 대시보드

`latest.json.theme_analysis.themes`의 각 테마에 속한 종목들의 **장중 평균 등락률**을 계산:

```
테마: AI/반도체
  대장주 평균 등락률: +2.1% (09:30 기준 +0.5% → 현재 +2.1%)
  외국인 순매수 합계: +150만주
  모멘텀: ↑ (상승 가속)

테마: 2차전지
  대장주 평균 등락률: -0.8% (09:30 기준 +1.2% → 현재 -0.8%)
  외국인 순매수 합계: -80만주
  모멘텀: ↓ (하락 전환)
```

**데이터 소스**: theme_analysis(테마→종목 매핑) + investor-intraday.json(수급) + intraday-history.json(등락률)

```
필요 작업:
- 프론트엔드: ThemeMomentumTracker 컴포넌트 신규
- 백엔드 변경: 없음 (기존 데이터 교차 활용)
```

## 5. 권장 우선순위

### Phase 1 — 즉시 적용 가능 (백엔드 변경 없음, 프론트엔드만)

1. **B-1**: `theme-forecast.json` 프론트엔드 통합
   - AIThemeAnalysis가 theme-forecast.json도 로드 → 최신 분석 표시
   - 가장 간단하면서 즉각적인 "최신성" 향상

2. **D-1**: 테마별 장중 성과 추적
   - 기존 theme_analysis 종목 매핑 + intraday-history.json으로 계산
   - "지금 어떤 테마가 살아있는가"를 직관적으로 파악

3. **A-1**: 장중 급등/급락 종목 하이라이트
   - intraday-history.json에서 최근 구간 등락률 급변 종목 추출
   - 홈 탭 상단에 "장중 급변 종목" 섹션 추가

### Phase 2 — 백엔드 소규모 개선

4. **B-2**: Gemini 재예측에 수급 데이터 추가
   - forecast_main.py 프롬프트에 외국인/기관 순매수 TOP10 추가
   - AI 예측의 정확도와 실시간성 동시 향상

5. **C-1**: 실시간 종합 점수
   - 프론트엔드 클라이언트 사이드 계산
   - 점수 기반 정렬 옵션 추가

### Phase 3 — 중장기

6. **A-3**: 거래대금 순위 변동 추적
7. **B-3**: 장중 재분석 빈도 확대 (11:30, 14:30 추가)

## 6. 결론

현재 프로그램의 1일 지연 문제는 **이미 수집 중인 장중 데이터를 분석/표시에 활용하지 않는 것**이 주된 원인이다.
신규 API 연동이나 대규모 인프라 변경 없이, **프론트엔드 데이터 가공**과 **기존 장중 AI 재예측 결과의 통합**만으로
상당 부분 해소할 수 있다.

가장 즉각적이고 효과적인 조치는:
1. `theme-forecast.json`을 프론트엔드에 직접 반영 (10:00/13:00 재예측 결과 노출)

3. Gemini 재예측에 수급 변동 데이터를 추가 투입하여 예측 정확도 향상
