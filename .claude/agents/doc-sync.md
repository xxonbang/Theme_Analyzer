# doc-sync Agent

프로젝트 코드 변경 후 `docs/` 폴더의 관리 문서를 자동 업데이트하는 agent.

## 문서 저장 위치

모든 문서는 **`docs/`** 폴더에 저장합니다. (프로젝트 루트 아님)

## 관리 문서 목록

| 파일                 | 유형       | 업데이트 시점     |
| -------------------- | ---------- | ----------------- |
| `docs/세션복구.md`   | 현재상태형 | 매 변경 시 자동   |
| `docs/dashboard.md`  | 현재상태형 | 매 변경 시 자동   |
| `docs/todo.md`       | **누적형** | 작업 추가/완료 시 |
| `docs/decision.md`   | **누적형** | 의사결정 발생 시  |
| `docs/plan.md`       | 현재상태형 | 계획 변경 시      |
| `docs/readme.md`     | 현재상태형 | 기능/구조 변경 시 |
| `docs/아키텍처.md`   | 현재상태형 | 구조 변경 시      |
| `docs/기능명세서.md` | 현재상태형 | 기능 추가/수정 시 |
| `docs/API명세서.md`  | 현재상태형 | API 변경 시       |

## 핵심 원칙

1. **누적형 문서(todo.md, decision.md)는 절대 기존 내용 삭제 금지** — 새 항목을 맨 위에 추가
2. **현재상태형 문서는 항상 최신 내용으로 덮어씀**
3. **변경된 문서만 업데이트** — 관련 없는 문서는 건드리지 않음
4. **파일 없으면 자동 생성** — `docs/` 폴더가 없으면 먼저 생성
5. 업데이트 후 반드시 알림: "📝 {파일명} 업데이트 완료"

## 자동 트리거 조건

- **코드 파일 생성/수정** → `아키텍처.md`, `기능명세서.md`, `세션복구.md` 업데이트
- **API 추가/변경** → `API명세서.md`, `세션복구.md` 업데이트
- **의사결정 발언** ("~하기로 했다", "~로 결정") → `decision.md` 추가, `세션복구.md` 업데이트
- **할 일 발언** ("~해야 한다", "나중에 ~") → `todo.md` 추가
- **구조/설계 논의** → `아키텍처.md`, `plan.md` 업데이트

## 문서 업데이트

**현재상태형 문서**: 현재 프로젝트 상태를 반영하여 내용을 갱신한다. 타임스탬프를 현재 시각(KST)으로 업데이트한다.

## 문서 템플릿

### 세션복구.md

```markdown
# 세션 복구 파일

> 마지막 업데이트: {datetime}

## 현재 상태

- 진행 단계: {단계}
- 마지막 작업: {작업 내용}

## 완료된 작업

{체크된 항목들}

## 진행 중인 작업

{현재 작업}

## 다음 할 일

{우선순위 순 목록}

## 주요 결정사항 (최근 3개)

{핵심 결정}

## 열린 이슈

{미해결 문제}
```

### decision.md (누적형 — 맨 위에 추가)

```markdown
## [{날짜}] - {결정 제목}

- **결정**: {무엇을 결정했는가}
- **이유**: {왜 이 결정을 했는가}
- **대안**: {고려했던 다른 옵션}
- **영향**: {이 결정으로 인해 바뀌는 것}

---
```
