# Project Doc Sync 스킬

코딩 프로젝트 진행 중 문서를 자동으로 생성·누적·업데이트하고, 세션 복구를 지원하는 스킬.

---

## 관리 문서 목록

| 파일            | 유형       | 업데이트 시점     |
| --------------- | ---------- | ----------------- |
| `세션복구.md`   | 현재상태형 | 매 변경 시 자동   |
| `dashboard.md`  | 현재상태형 | 매 변경 시 자동   |
| `todo.md`       | 누적형     | 작업 추가/완료 시 |
| `decision.md`   | 누적형     | 의사결정 발생 시  |
| `plan.md`       | 현재상태형 | 계획 변경 시      |
| `readme.md`     | 현재상태형 | 기능/구조 변경 시 |
| `아키텍처.md`   | 현재상태형 | 구조 변경 시      |
| `기능명세서.md` | 현재상태형 | 기능 추가/수정 시 |

**현재상태형**: 항상 최신 상태로 덮어씀  
**누적형**: 기존 내용 유지하고 새 항목을 추가함

---

## 슬래시 명령어

| 명령어           | 동작                                                        |
| ---------------- | ----------------------------------------------------------- |
| `/resume`        | 세션복구.md를 읽고 "여기까지 했어요, 이어서 할까요?" 출력   |
| `/status`        | dashboard.md 기반 현재 진행상황 요약 출력                   |
| `/save`          | 현재 대화 기반으로 세션복구.md + dashboard.md 즉시 업데이트 |
| `/todo`          | todo.md 출력 및 업데이트                                    |
| `/decision`      | decision.md에 새 의사결정 추가                              |
| `/plan`          | plan.md 출력 및 업데이트                                    |
| `/docs [문서명]` | 특정 문서 또는 전체 문서 업데이트                           |
| `/docs all`      | 모든 관리 문서 일괄 업데이트                                |

## 자동 트리거 조건

다음 상황이 감지되면 관련 문서를 **사용자 요청 없이 자동** 업데이트:

- **코드 파일 생성/수정** → `아키텍처.md`, `기능명세서.md`, `readme.md`, `세션복구.md`
- **"~하기로 했다", "~로 결정"** 발언 → `decision.md`, `세션복구.md`
- **"~해야 한다", "나중에 ~"** 발언 → `todo.md`, `세션복구.md`
- **구조/설계 논의** → `아키텍처.md`, `plan.md`, `세션복구.md`
- **대화 마무리 감지** → `세션복구.md`, `dashboard.md` 자동 저장

### 세션복구.md 자동저장 규칙

- **매 의미있는 변경마다 자동 저장** — 코드 수정, 결정, 기능 추가 등 변경이 생길 때마다
- `/save` 명령어로 즉시 강제 저장도 가능
- 저장 시 타임스탬프 갱신 및 "💾 세션복구.md 저장됨" 알림 출력

## 세션 시작 시 동작

새 세션이 시작되면 Claude는:

1. **`docs/`**폴더에서 `세션복구.md` 파일 존재 여부 확인
2. 있으면 → 내용을 읽고 아래 형식으로 요약 출력:

```
📂 프로젝트: [이름]
🕐 마지막 세션: [날짜/시간]
✅ 완료된 작업: [목록]
🔄 진행 중: [현재 작업]
⏭️ 다음 단계: [예정 작업]

이어서 작업할까요? (/resume 로 전체 컨텍스트 불러오기)
```

3. 없으면 → 프로젝트 초기화 제안 및 문서 구조 생성 여부 확인

## 문서 형식 템플릿

### 세션복구.md

```markdown
# 세션 복구 파일

> 마지막 업데이트: {datetime}

## 프로젝트 개요

{프로젝트 한줄 설명}

## 현재 상태

- 진행 단계: {단계}
- 마지막 작업: {작업 내용}
- 현재 작업 중인 파일: {파일 목록}

## 완료된 작업

{체크된 항목들}

## 진행 중인 작업

{현재 작업}

## 다음 할 일

{우선순위 순 목록}

## 주요 결정사항 (요약)

{핵심 결정만 최근 3개}

## 열린 이슈 / 막힌 부분

{현재 해결 안 된 문제}

## 파일 구조 (현재)

{현재 디렉토리 구조}
```

### decision.md

```markdown
# 의사결정 기록

## [날짜] - {결정 제목}

- **결정 내용**: {무엇을 결정했는가}
- **이유**: {왜 이 결정을 했는가}
- **대안**: {고려했던 다른 옵션}
- **영향**: {이 결정으로 인해 바뀌는 것}

---
```

```markdown
- 현재 스프린트: {설명}

## 완료 ✅

{완료 항목}

## 진행 중 🔄

{진행 항목}

## 대기 ⏳

{대기 항목}

{이슈 항목}
```

## 문서 업데이트 원칙

1. **누적형 문서는 절대 기존 내용 삭제 금지** — 항상 맨 위 또는 맨 아래에 추가
2. **업데이트 후 반드시 사용자에게 알림** — "📝 decision.md 업데이트했어요 (새 항목 1개 추가)"
3. **불확실한 내용은 `[?]` 태그로 표시** — 사용자 확인 요청
4. **파일이 없으면 자동 생성** — 존재하지 않는 문서는 템플릿으로 새로 생성
5. **변경된 문서만 업데이트** — 관련 없는 문서는 건드리지 않음

---

## 프로젝트 초기화 (/init)

새 프로젝트 시작 시 `/init` 또는 "프로젝트 문서 초기화해줘" 요청이 오면:

1. 프로젝트 이름, 설명, 기술 스택 질문
2. 위 9개 문서를 **`docs/`** 폴더에 템플릿 기반으로 일괄 생성
3. `세션복구.md`에 초기 상태 기록
4. "문서 구조 생성 완료" 보고

> 모든 문서는 **`docs/`** 폴더에 저장 (프로젝트 루트 아님)
